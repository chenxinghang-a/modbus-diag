# 上板验证清单

> 用途：**第一次拿到实物板时按顺序走一遍**，把只能在硬件上确认的事情一次性过掉。
> 开发阶段所有验证都在主机侧（71 项断言）和模拟器（45 项断言）上完成，
> 下面这些**只有真机能确认**。

## 0. 烧录与首启

```bash
idf.py -p COM3 flash monitor
```

| 检查 | 预期 | 不符时先查 |
|---|---|---|
| 串口有启动日志 | `=== Modbus Diagnostic Tool ===` | USB 线是否数据线、驱动是否装（CH340/CP210x） |
| RS-485 参数被恢复 | `RS-485 restored: 9600 baud, parity 0, timeout 100 ms, retry 2` | NVS 未初始化（首次烧录正常，用默认值） |
| 无重启循环 | 日志持续，不反复出现启动行 | 多半是供电不足或 PSRAM 配置不符 |
| 屏亮且有画面 | 主页菜单可见 | 背光 GPIO7、SPI 接线（MOSI11/SCK12/CS10/DC9/RST8） |

## 1. 显示与按键

| 操作 | 预期 | 不符时先查 |
|---|---|---|
| UP/DOWN 翻菜单 | 高亮跟着走，无重影 | 按键 GPIO（UP1/DOWN2/OK42/BACK41）与上拉 |
| OK 进子页 | 页面切换正常，BACK 能逐级返回 | 页面栈深度 8，超了会丢最老的一层 |
| **按住 OK 约 1 秒** | 触发"长按"（扫描页切模式、详情页提交/重扫） | 阈值 800ms；若手感太灵敏/太难触发，调 `BTN_LONG_PRESS_MS` |
| 快速连按 UP | 不丢键、不重复 | 消抖 30ms，机械抖动大的按键可加大 |

## 2. RS-485 基本通信

接一台真实从站（或 PC 上的 Modbus Slave），地址 1，9600bps。

| 检查 | 预期 | 不符时先查 |
|---|---|---|
| 设置页把波特率调到从站值 | 值保存，重启后仍是该值 | 串口日志 `RS-485 restored:` 那行 |
| 扫描页"快速模式"扫 | 能发现该从站 | 先查 A/B 是否接反、终端电阻 |
| 详情页长按 OK 重新分类 | 出现寄存器组列表 | 从站是否支持 FC03 |

## 3. 扫描（两种模式）

| 检查 | 预期 | 参考数据（论文表 6-5） |
|---|---|---|
| 快速模式 9600，超时 500ms，1~247 | 找到设备，显示 `Found n / 247 addr, x.xs` | 理论下限 247×500ms ≈ 123.5s |
| 快速模式 38400，超时 200ms，1~247 | 明显更快 | 理论上限的一半 |
| 全档模式（长按 OK 切换） | 依次跑 5 档波特率，耗时约为快速模式的 5 倍 | 界面上会显示 `Mode: ALL baud` |

> ⚠️ 扫描耗时是论文实测数据的关键支撑。若实测与表中量级差很多，先确认设置页的超时是否真的生效
> （扫描器读的是 `modbus_timeout` 配置，不是写死的值）。

## 4. 报文抓包

主站（Modbus Poll）以 200ms 周期发 FC03，本机进抓包页按 OK 开始。

| 检查 | 预期 | 不符时先查 |
|---|---|---|
| 帧列表出现条目 | 每帧一行，带毫秒时间戳 | 抓包要求 UART 空闲；若 Modbus 主站正在跑会启动失败 |
| 错误率、FPS 有数 | FPS 随发包频率变化，不恒为 0 | 本轮修过 `traffic_stats_tick()`，若恒 0 说明没调到 |
| 响应时间显示 `-- (passive, no timing)` | 被动抓包量不出往返时间，属正常 | 不要误认为故障 |

## 5. 波形（GPIO5 / ADC1_CH4）

信号发生器给 1kHz 正弦，幅度落在 0~3.1V（分压后）。

| 检查 | 预期 | 不符时先查 |
|---|---|---|
| 开始后出现波形 | 连续刷新、不撕裂 | 双缓冲改造过；撕裂说明读的是正在写的缓冲 |
| Vpp / DC 与信号源一致 | 误差 <5% | 1/4 分压比（30K/10K）是否与固件换算一致 |
| Trigger: YES | 有上升沿时能锁到 | 阈值写死 2048，若信号幅度小可能永远不触发 |

## 6. 诊断页与报告

| 检查 | 预期 | 不符时先查 |
|---|---|---|
| 未采数据时进诊断页 | 显示 `Score: -- (No Data)`，进度条为空 | 不应显示 100 分（旧版本会） |
| 抓过包后再进 | 显示真实分数、帧数、错误率 | 切页不会清零统计（`ensure_init`） |
| 底部显示 `Last EXC` + `Fix:` | 有异常后出现，两行都在屏内（y=206/220） | 若压边或被裁，调这两个 y |
| UP 导出报告 | 日志出现 report exported | SPIFFS 是否挂载 |
| 长按 OK 开始监测 | 分数随总线活动变化 | UART 被 Modbus 主站占用时会提示 `UART busy!` |

## 7. Web 与 TCP

手机连 `ModbusDiag` / `12345678`，浏览器开 `http://192.168.4.1/`。

| 检查 | 预期 |
|---|---|
| `/` | 首页三个链接 |
| `/report` | 优先返回 HTML（深色主题，四张卡片）；无报告时 404 |
| `/log` | 纯文本操作日志，能看到 scan/config/write 记录 |
| TCP 页连从站 | 连上后 OK 做一次读测试，`Last resp` 有微秒数 |
| **拔掉从站网线后再请求** | 应报错并**自动回退到 RS-485**（而不是永远卡在"已连接"） |

> TCP 断线回退、事务号校验、超时按配置生效 —— 这三项本轮刚修，**只能用真机验证**。

## 8. 本轮改动重点复查（最容易出问题的地方）

1. **长按 800ms 手感**：扫描页长按切模式、详情页长按提交/重扫。
   如果太容易误触（想翻页却切了模式），把 `BTN_LONG_PRESS_MS` 调到 1000~1200。
2. **设置页 5 行的对齐**：`Baud / Timeout / Retry / AP Name / About` 的值是用
   `ui_list_item_draw` 在菜单行上覆盖绘制的，若出现重影或错位，说明行高 `MENU_ITEM_H`（28）与实际不符。
3. **诊断页底部两行**（y=206 / y=220）是否压到屏幕下沿。
4. **写寄存器**：编辑态是 5 个数字框，UP/DN 改当前位，OK 下一位，长按 OK 立即提交。
   提交后必须看到 `OK @addr readback=xx`；如果 readback 与写入不一致，说明从站做了钳位（正常现象，报告里会如实显示）。
5. **扫描模式切换**：`Mode: ALL baud` / `Mode: QUICK @9600` 两行是否正常显示。

## 9. 常见故障速查

| 现象 | 最可能的原因 |
|---|---|
| 白屏/花屏 | SPI 接线或 `TFT_SPI_FREQ_HZ` 太高（先降到 20MHz 试） |
| 能发不能收 | DE/RE（GPIO4）方向控制时序，或 A/B 接反 |
| 扫描一个都找不到 | 超时太短（50ms 对某些从站不够）、波特率不对、终端电阻缺失 |
| 抓包全是 CRC 错 | 波特率与实际总线不符 |
| 波形是一条直线 | ADC 输入未接或分压电阻装错 |
| 报告写不进去 | SPIFFS 满（日志有 8KB 轮转，报告没有） |
