# 可用性分析：为什么它现在还用不了

> 结论先行：**代码不是主要阻塞，物理载体才是。**
> 这份固件可以编译、可以通过 181 项测试、可以和第三方 Modbus 从站互通，
> 但它**从来没有在真实硬件上运行过一分钟**——因为没有板子。
> 而"没有板子"这件事，比你以为的更容易解决：见 §4 路径 A。

---

## 1. 三个层次的阻塞

| 层次 | 阻塞 | 性质 |
|---|---|---|
| L1 物理 | 无原理图、无 PCB、无焊接整机 | **硬阻塞**：固件没有运行载体 |
| L2 验证 | 从未上板，UI 布局/按键手感/485 时序/ADC 精度全部未验 | 风险：纸面正确 ≠ 实际可用 |
| L3 功能 | 一批参数与场景缺口 | 影响"好不好用"，不影响"能不能跑" |

---

## 2. 逐项问题清单

### L1 物理层（硬阻塞）

| # | 问题 | 表现 | 原因 | 影响范围 | 修复 | 优先级 |
|---|---|---|---|---|---|---|
| P1-1 | 无原理图 | `hardware/` 只有 netlist/BOM/布局坐标，没有 `.kicad_sch` | 无人绘制 | 电气毕设核心交付物缺失，评委必问；无法 ERC | 按 `netlist.json` 画 6 张分页图，ERC 清零 | **P0** |
| P1-2 | 无 PCB | `modbus-diag.kicad_pro` 是空壳 | 依赖 P1-1 | 无法打样、无法出 Gerber | 按 `placement.csv` 布线，DRC 清零 | **P0** |
| P1-3 | 无焊接样机 | — | 依赖 P1-2 | 所有功能零实物验证 | 见 §4 路径 A（可跳过 P1-1/P1-2 先解决） | **P0** |

### L2 验证层（未验证即不可信）

| # | 问题 | 表现 | 原因 | 影响范围 | 修复 | 优先级 |
|---|---|---|---|---|---|---|
| P2-1 | UI 从未被眼睛看过 | 320×240 下的文字截断、重叠、越界都可能存在 | 无截图能力 | 用户第一印象 | 用 `docs/上板验证清单.md` 逐项拍屏 | **P0** |
| P2-2 | 长按 800ms 未验证 | 可能误触（想翻页却触发功能） | 阈值拍脑袋 | 交互体验 | 上板调 `BTN_LONG_PRESS_MS` | P1 |
| P2-3 | 485 方向切换时序未实测 | 半双工收发在 115200 下可能丢首字节 | `esp_rom_delay_us(10)` 是理论值 | 高速通信可靠性 | 逻辑分析仪抓 DE/DI/RO 波形 | **P0** |
| P2-4 | ADC 分压比未实测 | 波形页显示的 Vpp/电压可能偏 20% | 1/4 分压按标称电阻算 | 波形结论可信度 | 信号发生器给已知幅度，比对读数 | P1 |
| P2-5 | TCP 断线/重连未实测 | 刚修的逻辑（关 socket、自动回退串口）没有真机证据 | 需要真从站 | 该修复是否有效未知 | 见清单 §7 | P1 |

### L3 功能层（能跑但不好用）

| # | 问题 | 表现 | 原因 | 影响范围 | 修复 | 优先级 |
|---|---|---|---|---|---|---|
| P3-1 | 扫描范围固定 1~247 | 只想看 1~30 也要等满全程（分钟级） | 界面无入口 | 现场效率 | 设置页加 `Scan Range` 循环项，复用 cfg.addr_start/end | P1 |
| P3-2 | TCP 端口固定 502 | 连不上非标端口设备 | 界面无入口 | 兼容性 | 设置页加端口步进（±1/±10） | P1 |
| P3-3 | AP 密码/SSID 写死 | 现场无法改名改密码 | 四键机身限制 | 部署安全 | 保持现状，写入 README/论文；或加简单 PIN 方式改 | P2 |
| P3-4 | 批量写只支持同值填充 | 不能写一组不同值 | UI 简化取舍 | 参数下发能力 | 支持值序列逐位编辑（可延后） | P2 |
| P3-5 | 无 RTC | 日志/报告时间戳是开机相对时间 | 未接 RTC 芯片 | 报告无法对应真实时刻 | 接入 SNTP（AP 模式下也可用） | P1 |
| P3-6 | 看门狗不 panic | 任务卡死只刷警告不恢复 | `CONFIG_ESP_TASK_WDT_PANIC` 未开 | 与 NFR2 承诺不符 | 开 panic，但要先确认长扫描不会触发（扫描已异步化，风险可控） | P1 |
| P3-7 | UI 层无自动化测试 | 改页面只能靠肉眼回归 | 页面逻辑与渲染耦合 | 长期维护 | 抽纯函数状态机进 host_tests | P2 |

## 3. 当前 CI 暴露的问题（已修，但说明风险仍在）

今天 CI 抓到的三次失败，全是**同一类根因**：Windows 本地能过、Linux 挂。

| 失败 | 原因 | 修复 |
|---|---|---|
| `size_t` 未定义 | MinGW 的头文件顺带带出 `size_t`，glibc 不会 | 头文件补 `<stddef.h>` |
| `struct timeval` 未定义 | Windows 分支用 `DWORD` 设超时，Linux 要 `<sys/time.h>` | 补头文件 |
| `sqrtf` 未定义 | MinGW libgcc 自带数学函数，glibc 要显式 `-lm` | 链接加 `-lm` |

**含义**：本地全绿不等于别人机器上能跑。CI 不是装饰，是这个项目目前唯一的环境交叉验证手段。

## 4. 两条可用路径

### 路径 A：一天内拿到"能用的原型"（推荐先做）

**不需要画 PCB，不需要等打样。**

材料（网购，约 150~250 元）：
- ESP32-S3 开发板一块（带 USB，带 4~8MB Flash）
- ILI9341 2.8" SPI 显示屏模块一块（多数自带 XPT2046）
- RS-485 收发模块一块（如带 MAX3485 的 TTL 转 485）
- 4 个轻触按键 + 杜邦线 + 面包板

接线（按 `hardware/README.md` 的引脚表）：

| 功能 | ESP32-S3 引脚 |
|---|---|
| TFT SCK/MOSI/CS/DC/RST/BL | 12 / 11 / 10 / 9 / 8 / 7 |
| 按键 UP/DOWN/OK/BACK | 1 / 2 / 42 / 41 |
| 485 DI/RO/DE | 17 / 18 / 4 |
| ADC 波形输入 | 5 |
| 485 A/B | 接模块 A/B |

步骤：
1. 烧录现有固件（`idf.py flash`）
2. 走 `docs/上板验证清单.md` 第 0~2 步（启动、显示、按键）
3. 用 PC 上的 `sim/modbus_sim.py` 当从站，或用任何 Modbus 从站设备
4. 逐项验证并把结果回填清单

**产出**：一台真的能拿在手里的样机 + 一份填了实测值的验证记录 + 论文 6.x 的真实数据来源。

### 路径 B：完整毕设交付（3~5 天，需在 A 之后或并行）

1. 按 `netlist.json` 画原理图 → ERC 清零 → 导出 PDF
2. 按 `placement.csv` 布线 → DRC 清零 → Gerber
3. 打样（嘉立创 3~5 天）→ 焊接 → 复跑路径 A 的清单
4. 论文 6.2/6.5/6.8 数据用实测值替换

## 5. "修好了"的判定标准

| 层级 | 达标标准 | 现状 |
|---|---|---|
| 能跑 | 固件在真实硬件上启动、显示、按键有响应 | ❌ 未开始 |
| 能用 | 上板清单 60+ 项全部通过并回填实测值 | ❌ 未开始 |
| 可信 | 论文每条数据有原始记录且可复现 | ⚠️ 部分（测试类数据可，实测类否） |
| 可交付 | 原理图 ERC 0 / PCB DRC 0 / Gerber 可出 | ❌ 只有设计数据 |
| 可维护 | CI 绿 + 181 项测试 + 静态检查 | ✅ |

---

## 6. 一句话总结

**这个项目"用不了"不是因为代码写不出来，而是因为从来没有人把它接到真实世界上跑过一次。
而这件事，花 200 块和一天时间就能做到——见路径 A。**
