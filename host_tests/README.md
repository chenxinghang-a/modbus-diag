# host_tests/ —— 协议层主机侧回归

**不参与固件构建。** 这里放的是能在 PC 上直接跑的单元测试，用来在没有板子的情况下
证明协议层没被改坏。

## 为什么单独一套

固件测试要么有板子、要么得跑真机日志，改一行 CRC 都要烧一次录 —— 反馈太慢。
而 `modbus_rtu.c`（CRC / 建帧 / 解析）和 `frame_parser.c`（抓包帧解析）都是**纯 C**，
只依赖 `<string.h>` 和本工程头文件，用 gcc 就能跑。

## 跑法

```bash
bash host_tests/run.sh
```

需要 gcc（Windows 上 Git-Bash 自带 MinGW 的 `gcc` 即可），**不需要 ESP-IDF**。

## 覆盖什么

| 组 | 用例 |
|---|---|
| CRC16 | 经典向量 `01 03 00 00 00 0A` → 0xCDC5；查表法与逐位参考实现逐字节比对（1~64 字节随机数据） |
| 建帧 | FC03 请求帧长度/内容、广播帧（addr=0）、缓冲区不足返回负值 |
| 解析 | 请求帧 addr/qty、**响应帧按帧长识别为响应并给出字节数**、异常帧（0x83）异常码与功能码名、CRC 损坏、<4 字节与空指针边界 |
| T3.5 | 波特率越高静默时间越短；115200 下不低于 1750us |
| SMA 滤波 | window=1 恒等、window=3 与手算逐点比对、window=0 被夹到 1、长度 0 不写 |
| 幅值测量 | 方波 Vpp/DC、常量信号、**len=0 时返回 0（原实现会返回 4095 / 除零 panic）** |
| 触发检测 | 上升沿索引、只有下降沿、从未过阈值、首点不参与、恰好等于阈值算触发 |

当前：**协议层 31 项 + 信号处理 15 项 = 46 项断言，全绿**。

## 两个已经踩过的坑（写测试时别踩回去）

1. **CRC 的字节序**：`modbus_crc16()` 返回的是**寄存器值**，线上是低字节先发。
   `01 03 00 00 00 0A` 的寄存器值 = `0xCDC5`，帧尾两字节是 `C5 CD`。
   我第一版测试断言成 `0xC5CD`，直接假失败 —— 失败先怀疑断言，别急着改实现。
2. **响应帧不能当请求帧解析**：FC03 响应 `01 03 04 00 01 00 02` 若按请求解，
   会得到「addr=1024 qty=256」这种**看着像真数据的胡说八道**。现在按「长度 == 5 + 字节数」
   且「长度 != 8」判为响应。FC05/06 的请求与响应**同形**，无法区分，属已知限制。
3. **`signal_measure_dc()` 曾在 len=0 时除零**（ESP32 上整数除零是 panic，不是返回 0），
   `signal_measure_vpp()` 在 len=0 时返回 4095-0 这个凭空的满幅值。两个都加了长度守卫，
   测试固定住。

## 想接 CI 的话

`run.sh` 返回非零即失败，直接串进任意 CI 的 test 作业即可，不依赖 ESP-IDF 环境。
