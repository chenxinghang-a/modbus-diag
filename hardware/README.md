# 硬件设计包

> 与论文第 4 章一一对应。**本目录提供的是可核对的设计数据**（网表、BOM、引脚约束），
> 不是可以直接投产的 PCB：布局布线需在 EDA 里按本网表绘制。

## 文件

| 文件 | 作用 |
|---|---|
| `netlist.json` | **单一数据源**：元件表 + 网表（每个元件每个脚的归属网络） |
| `BOM.csv` | 由 `tools/gen_bom.py` 从网表生成，勿手改 |
| `tools/gen_bom.py` | 生成 BOM |
| `tools/check_hardware.py` | 自检：网表一致性 + 固件引脚一致性 + BOM 同步（35 项） |
| `tools/gen_placement.py` | 生成布局方案（坐标表 + SVG），并做几何自检：不重叠、不越界、接插件靠边 |
| `placement.csv` / `placement.svg` | 布局坐标与示意图（100×70mm 板框） |
| `modbus-diag.kicad_pro` | KiCad 工程骨架，等待按网表绘制原理图/PCB |

```bash
python hardware/tools/gen_bom.py          # 生成 BOM
python hardware/tools/check_hardware.py   # 自检，返回非零表示硬件与固件对不上
```

## 网表示例（节选）

```json
"RS485_DE": [["U1","IO4"], ["U2","DE"], ["U2","RE"], ["R7","1"]]
"ADC_IN":   [["U1","IO5"], ["R3","2"], ["R4","1"]]
```

含义：GPIO4 同时接 MAX3485E 的 DE 与 RE（半双工方向控制），并挂 10k 下拉保证上电即为接收态；
GPIO5 接 30k/10k 分压中点（分压比 1/4），测 A 线对地电压。

## 三个关键设计决定

**1. 两个 USB 不能并联。**
ESP32-S3 有原生 USB-OTG（GPIO19/20），本设计另有 CH340C 做 UART 下载。若两者都接到同一个
Type-C 的 D+/D−，上电后两颗器件会同时驱动总线。本设计**只把 CH340C 接到连接器**，
原生 USB 引到测试点预留。论文 4.2.4 的"保留原生 USB 作为备选"正是这个意思。

**2. 终端电阻做成跳线可选。**
120Ω（R6）经 JP1 串在 A/B 之间。工具挂在总线中段时不该并终端，只有做末端设备时才短接。
固定焊上去会让中段接入时总线负载过重。

**3. DE/RE 必须下拉。**
GPIO4 复位后是浮空输入，若不加上下拉，MAX3485E 可能上电即进入发送态，把总线拉死。
R7 = 10k 下拉，保证默认接收。这条也是现场"上电后整条总线不通信"的常见原因。

## 电源与热

| 项 | 值 | 依据 |
|---|---|---|
| 输入 | USB-C 5V（CC1/CC2 各 5.1k 下拉） | 受电端必须下拉，否则 PD 电源不出 5V |
| 稳压 | AMS1117-3.3（SOT-223） | 论文 4.2.1 |
| 估算负载 | ≈352mA | 模组 240 + 背光 80 + 485 2 + 其它 30 |
| 线性耗散 | (5−3.3)×0.352 ≈ **0.6W** | SOT-223 必须 ≥100mm² 铺铜散热 |
| 保护 | PTC 1A + SMBJ5.0A + A/B 各一只 SMBJ6.5CA | 论文 4.2.1 / 4.3.2 |

> 若后续把背光调到更亮或加触摸驱动，352mA 的余量会被吃掉，届时应改用同步 Buck（如 MP2315），
> 否则 AMS1117 结温会超限。这一条写在这里，免得改版时忘掉。

## 自检覆盖什么

`check_hardware.py` 共 32 项，重点是**固件与硬件不许悄悄分叉**：

- 网表内部：端点存在、同一 pin 不接两个网、无悬空元件、GND/3V3 完整
- **固件 ↔ 硬件**：`app_config.h` 里 16 个引脚宏逐个核对"该 GPIO 是否真的连到了期望的网络"
- **历史坑**：ADC 通道与 RS-485 方向脚不能是同一个 GPIO（论文 4.3.1 记录过的冲突）
- 关键连接：MAX3485E 的 RO/DI/DE/RE、CH340C 的 UD±、原生 USB 未接连接器
- BOM 与网表同步、每个元件都有 MPN

已做过变异验证：把 MOSI 从 GPIO11 改到 GPIO13，自检立刻报
`TFT_PIN_MOSI=GPIO11 → SPI_MOSI 网表中该脚在 <未连接>`。

## 原型机搭建（不用等 PCB）

`PROTOTYPE.md`：用开发板 + 外购模块一天内搭出可用样机的接线表、
不要占用的脚（USB/Flash/PSRAM/JTAG）、烧录步骤与常见现象排查。

## 布局方案

`placement.csv` / `placement.svg` 给出 49 个元件在 100×70mm 板框内的坐标，按功能分块：
电源链（左上）· 主控（中上）· RS-485（右上）· 下载/USB（左中）· 显示接口（中下）· 按键（下排）。

自检项（`gen_placement.py` 每次运行都检查，也进了 CI）：
- 每个元件都在板框内且距板边 ≥3mm
- 任意两个元件间距 ≥0.6mm（含丝印余量）
- USB-C 与 RS-485 端子必须靠板边
- 坐标表里的元件与网表**完全一致**（多一个少一个都报错）

> 尺寸按封装标称值估算（0402=1.0×0.5、SOIC-8=4.9×3.9 等），落板前需按实际封装库复核。

## 还没做的

- **PCB 布局布线**（KiCad 工程为空骨架）。需要按 `netlist.json` 在 EDA 里绘制；
  布局要点：去耦电容距引脚 ≤3mm、USB 差分对等长、RS-485 差分对 100Ω、AMS1117 铜箔 ≥100mm²。
- **原理图图形文件**：网表是该图的等价数据表示，但没有出图。
- **EMC/ESD 实测**、**热成像复核**：需实物。

## 触控引脚的现状

XPT2046 与 ILI9341 共用 SPI：`T_CLK` 已并到 SCK、`T_DIN` 并到 MOSI（见网表）。
`T_DO`（触摸数据输出）**尚未引出** —— 启用触控时需要飞一根线到空闲 GPIO（如 GPIO13），
并在 `app_config.h` 增加 MISO 定义。本版固件不使用触控，`T_CS`/`T_IRQ` 作为预留。
